# Как контрибьютить в doc2md

Спасибо, что хотите помочь. Самые ценные вклады: подтверждённые баги на реальных
документах (особенно `.pptx`/`.xlsx`/`.pdf`/`.epub` — они помечены как не
покрытые живыми тестами), проверка на Windows и уточнение трактовки кодов
возврата anydoc.

## Настройка окружения

Ничего специального не нужно — только Node.js 18+ (он и так требуется для
`npx`/anydoc):

```bash
git clone https://github.com/ilyautov/doc2md.git
cd doc2md
node --version   # 18+
```

## Проверки перед PR

```bash
node --check skills/doc2md/scripts/convert.js   # синтаксис Node-версии
bash -n       skills/doc2md/scripts/convert.sh   # синтаксис bash-версии
bash scripts/smoke.sh                             # smoke: --help + graceful missing-path
```

CI (`.github/workflows/ci.yml`) гоняет то же самое на каждый PR.

## Правила проекта

- **Две версии держим в синхроне.** `convert.js` (кросс-платформенная,
  основная) и `convert.sh` (Unix) должны вести себя идентично: одинаковая
  категоризация `OK` / `ПРОПУСК` / `ОШИБКА`, одинаковые имена выходных файлов
  (`<имя>.<расширение>.md`), одинаковые коды возврата. Меняешь одну — синхронизируй
  вторую в том же PR.
- **Источник правды скилла — `skills/doc2md/SKILL.md`.** Правки поведения
  отражай и там, и в `README.md`/`README.en.md`.
- **Честность про непроверенное.** Не переписывай раздел «Не тестировал» в
  «протестировано», пока сам не прогнал на реальном файле. Если проверил формат
  или Windows — обнови секцию и `CHANGELOG.md`.
- **Не раздувай зависимость.** Скилл намеренно тонкий: обёртка над anydoc, а не
  свой парсер. Новую логику добавляем, только если она про пакетную обработку /
  сводку / маршрутизацию, а не про сам разбор форматов.

## Что НЕ является багом doc2md

- Сканы и PDF-картинки без текстового слоя не читаются — у anydoc нет OCR. Это
  ограничение движка, файл штатно уходит в `ПРОПУСК`. Такие репорты лучше
  адресовать апстриму [firecrawl/anydoc](https://github.com/firecrawl/anydoc).
